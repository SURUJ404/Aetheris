# `agentic.v1` Protobuf Contract

This directory is the versioned boundary between the Rust control plane and the
Python cognitive service.

## Rules

1. **Additive changes only within v1.** Never renumber or reuse a field.
2. Reserve removed field numbers and names with `reserved`.
3. Breaking changes require a new package (`agentic.v2`), never a silent edit.
4. Python proposals are untrusted. Rust validates identity, schema, budgets,
   policy and approval before any tool executes.
5. `RequestContext.tenant_id` must match the authenticated caller. It is never
   accepted from an end client.
6. `arguments_json` is validated against the tool's JSON Schema and canonicalized
   by Rust before hashing for approval.
7. Fatal errors use a gRPC status plus a protobuf `ErrorDetail` in the
   `agentic-error-bin` trailing metadata key. Non-fatal issues use `Warning`.
8. Trace context uses W3C `traceparent`/`tracestate`. Every request carries
   `request_id`, `task_id` and `idempotency_key`.

## Generation

Rust bindings are generated automatically by
`services/rust-control-plane/build.rs` using `tonic-prost-build` and the
vendored `protoc` binary.

Python bindings are generated by:

```powershell
docker run --rm -v "$PWD:/work" -w /work python:3.12-slim bash -c "pip install -q grpcio-tools==1.74.0 && python services/python-cognitive/scripts/gen_proto.py"
```

The Python generator rewrites protoc's absolute imports to relative imports so
the generated package remains importable as `app.gen.agentic.v1`.

## Compatibility tests

- Rust: `services/rust-control-plane/tests/proto_contract.rs`
- Python: `services/python-cognitive/tests/test_proto_contract.py`

Both suites pin field numbers and round-trip behavior. A renumbering change must
fail CI.
